# 登录与前端入口交付

## 2026-09-08 兼容性修复

在当前内置浏览器中，HTML/CSS 正常加载，外部 JavaScript 请求在收到底层 HTTP 响应后未完成页面加载。禁用缓存无效；独立本地最小页面中内联脚本执行成功，而 `text/javascript` 和 `application/javascript` 外部脚本均未执行。因此不能将问题归因于密码、React 业务代码或单一 MIME 类型。

- 登录保留原加密 JSON 协议，增加原生 POST 表单路径；密码不会放入 URL、错误提示或日志，校验失败不创建会话。远程部署仍应使用 HTTPS。
- `_render_spa` 把当前 Vite 单文件入口嵌入 HTML，保留模块语义和外部 CSS；仅接受构建目录中的受限平面文件名，并转义脚本结束标签。
- 页面使用 `Cache-Control: no-store`，避免旧 HTML 引用过期入口。代价是每次页面导航重新传输入口代码（当前约 318 KB），不单独缓存该入口。
- 当前构建入口没有动态导入或 `import.meta`。未来若引入分包或相对模块导入，必须同步调整交付策略并重新做浏览器验收。

回归测试：`python -m unittest tests.module.test_web_login tests.module.test_spa_delivery`。

本修复是项目侧兼容措施，不代表已经修复或确认内置浏览器内部的具体故障。没有关闭浏览器安全设置。

后续验证：内置浏览器已渲染资源库外壳，但 JSON 和 SSE 请求也在底层响应后停滞，尚未完成数据列表验收。独立 HTTP 客户端验证资源库三个分类均返回正常（5、0、1 项）。因此嵌入入口只能解决外壳白屏，不能作为整体恢复的证明；需要对比其他浏览器以定位剩余阻塞。

## 账户与配置显示保护

Chrome 对比确认能显示两个数据库账户并建立实时连接。项目现在把与 `/api/bootstrap` 相同的初始化数据嵌入受登录保护的 HTML（JSON 中转义 HTML 特殊字符，页面禁止缓存），不依赖后台请求才能显示已保存的配置。未登录请求仍跳转登录，不返回初始化数据。

前端区分加载中、加载成功、加载失败；等待包含响应正文读取的 15 秒超时，不把失败转换为空配置。即使初始数据来自 HTML，也必须完成后台接口验证后才允许编辑保存配置。内置浏览器后台请求仍不响应时，只读展示并明确提示使用 Chrome 编辑；不声称浏览器底层问题已修复。

新增回归：`node --import ./webui/node_modules/tsx/dist/loader.mjs --test tests/webui/bootstrap.test.ts`。
