# 视频剧情与片段总结

## 验收目标

简介回答“主要发生了什么、如何发展”，不是房间、构图、衣着或姿势清单。有证据才写剧情；有具体活动内容时显示“片段内容”，证据不足时显示“剧情待确认”。仅有“参与者进行成人亲密互动”等单句分类级标签不算合格简介，显示“简介待完善”。未知背景、关系、因果与结局不能补写。

真实验收范围仅 308、312、318、40696，原服务 https://cpa.007666.xyz，仅 grok-4.6。用户已授权这四项的抽帧、可靠本地转写、派生事件与候选简介；不向模型发送原视频，不涉及 307、317 等图片资源，不切换模型或绕过拒绝。

## 生产路径

1. 分类与分类维度核验维持原流程；显式“更新简介”复用已确认分类。
2. 按时间窗提取有界证据。默认长视频 24 帧、8 窗、180 秒语音预算：前 60 秒、末 60 秒及分散在中间的 60 秒。最低 6 帧仍保留开、中、末三组；少量抽帧不代表看过全片。
3. 长于 300 秒且有时间窗的视频，先单独读取末窗最多 3 张既有画面，再隔离读取同一最后一帧。不提供候选简介。末窗读取返回中性活动观察和可见性；隔离检查只返回 visible/not_visible/unclear，不同时要求描述活动。原末窗动作线索保留，独立可见性另标来源，映射回全局引用；观察冲突仍需对照原图核验，不能照抄结论。成人活动片段中，末段此前可见参与者或更早的独立主活动确认参与者存在、最后未见参与者时，应保留“不再出现在画面中”，不能改成活动结束或猜测去向。
4. 成人分类另行判断叙事模式，只返回模式、判定类别及证据引用。确定模式后，事件提取不能另选分支来输出自由细节；真正有目标、问题和发展证据的 story 分支仍然保留。activity 另选接近 20%、50%、80% 时间位置的最多 3 张既有帧，盲读主活动分类代码；重复确认的活动必须进入核心内容，不得被另一种活动替代。该步骤不读取旧简介或文件名。
5. 成人 activity 若有可靠转写，先用同一个 Grok 单独读取语音文本，不附加画面或文件名，提取最多两项可安全概括的具体含义。无具体内容、语义不连贯或不适合中性概括时返回空结果和固定原因码；拒绝或格式错误立即停止，不回退绕过。服务器将合格的候选含义合入事件记录，即使画面事件提取遗漏了语音也不能丢掉；所有候选仍须最终对照实际转写做事实核验。
6. 事件协议区分 core（主活动）、progression（实质发展）、context（可靠对白的具体含义）及 detail（局部观察）。细节先检查安全性与引用，再移出写作输入；真正的重要变化和具体对白含义不能删掉。服务器由实际引用计算事件时间。
7. 成人 activity 的 core/progression 使用封闭的中性活动/变化词项；不自由追加身体细节。若存在可靠转写，另允许 context 表达非露骨话题、明确请求、目的或明确设定，引用仅限实际 speech ID；无可靠转写就没有该协议分支。写作与事实核验均要求保留其具体含义，不能统一压成“交谈”。不从分类名称或文件名发明事实，不把人物离开视野等同于活动结束。
8. 写作策略在请求前选定：成人 activity 的 core/progression 全部属于上述封闭词项，context 是已通过本地检查且只引用可靠语音的单句中性陈述时，直接投影事件原文，禁止润色新增“开始”“结束后”等事实，也不再次压缩掉具体对白含义；1–3 个事件各成一句，更多事件将第三项起合为末句，全部保留引用并检查句长。该路径仍必须经过独立 Grok 事实核验，不是拒绝后的降级通道。story、非封闭活动词项及多句 context 继续使用独立写作，只看事件而不读取原图、文件名或不可靠转写。story 用 2–4 句，activity 用 1–3 句，覆盖主线首尾和每项 context；定向修正同样明确列出对白事件 ID。事件句保留至少 6 个中文字符、160 字符上限；不以正文总字数强迫填充。
9. 独立事实核验重新对照实际证据，检查每个事件、每句简介、模式、主次、覆盖、指代和重复。格式通过不是事实通过。失败候选不覆盖已有结果。若主活动和叙事模式成立，仅附加发展被明确否定，可删除被否定项、重新编号并做一次写作与复核；不能删除不受支持的核心活动来伪装成功。实际内容遗漏不能靠删事件纠正。

## 协议与限制

- summary_quality.version = 5，narrative.version = 2，audit.version = 2；下载分析缓存流程版本 30。
- 单句活动标签增加 `category_only_summary`，不进入无意义的独立审核或同义改写；上下文遗漏，或虽然引用了上下文却只写固定“交谈”标签，增加 `summary_drops_context`，允许一次基于原事件的表达修正。事实成立和对读者有用是两个条件，不能用前者代替后者。
- `diagnostics.dialogue_context` 只记录状态、项数和固定原因，不记录原始转写或被拒绝的正文。该阶段只在成人活动且有可靠转写时增加一次同服务请求，不扩大素材范围；失败诊断也保留这些脱敏字段。
- 对白候选的中文要求同时进入提示与 JSON Schema 的基础 `pattern` 字符类约束，本地仍核验长度与汉字数量；诊断仅增加这些计数。[xAI 的正则支持范围](https://docs.x.ai/developers/model-capabilities/text/structured-outputs)明确支持基础字符类和重复，未使用其不支持的前后向断言。原服务的合成对白兼容性测试通过，不等同于真实资源内容验收。
- 历史单句标签在资源列表、详情及目录读取时进行只读质量投影，归入待完善筛选；不修改数据库或 JSON 中的原始分析。前端公共投影也识别旧标签，使卡片、悬浮和详情一致。分类仍保持已确认。
- 每句绑定 event_refs，其 evidence_refs 由对应事件派生。前端卡片、悬浮、详情使用共同状态投影；依据与时间线默认折叠，旧版简介不能冒充新版通过。
- Grok 4.6 使用低推理量和 JSON 输出；模式、成人活动事件及事实核验使用严格 JSON Schema，返回对象还通过本地 jsonschema 检查。不符合结构就失败，不关闭约束重试。
- JSON Schema 支持参考 [xAI 官方文档](https://docs.x.ai/developers/model-capabilities/text/structured-outputs)。原代理的真实测试确认可用；这不证明输出内容必然正确。
- 基础完整视频路径为分类、核验、事件、写作、事实核验五次请求；简介更新省去前两次。成人分类另加一次模式判定；成人 activity 另加一次主活动核对，封闭事件投影省去一次写作请求；长视频另加末段观察、末帧独立观察各一次。均沿用相同有界证据，不增加抽帧或语音总预算，但增加对应模型输入费用。
- 暂时连接/服务失败按原策略最多重试一次。表达、格式及上述受限的附加事件纠正共用一次重写预算；随后必须获得新的完整核验通过。拒绝、不合适内容、模式冲突、无依据的核心活动不能靠重写变成通过。
- 核验的 coverage_ok=false 若明确是 unsupported_ending，属于虚构结尾，不等同于 missing_progression 等内容遗漏：结尾仅由正文添加时保留全部已支持事件重写；附加事件本身被否定时先移除该项。两种路径都不直接修改核验为通过，也不增加下载或提取轮数。
- 纠正后的事件子集必须重新满足独立主活动与末段变化检查，不能借“删除附加事件”抹掉已观察到的关键变化。主活动代码和末段可见性只保存白名单元数据，不保存被拒绝的正文。
- `diagnostics.summary_revision.strategy` 区分 `model_writing`（status=returned）与 `activity_projection`（status=projected）。投影不合格时不调用自由写作掩盖问题，也不重复审核同一正文；只有上述安全的附加事件删减可重新投影、再审核一次。
- 若独立观察已确认此前参与者存在、最后一帧未见参与者，而事件仅引用这一缺席帧却声称停止活动、结束表演或主动离开，服务器将该 progression 收窄为“不再出现在画面中”；若模型事件中遗漏此状态变化，则由独立观察补入带该帧引用的事件。重新验证整个事件记录，并执行完整 Grok 事实核验。不改核心活动、不改 story、不改写其他画面或语音支持的事件，也不删除这些事件来伪装通过。拒绝仍立即停止。诊断 `ending_event_projection` 只记录受影响的事件 ID 和固定来源代码。
- 上述缺席状态若同时引用末窗中此前可见的画面，仅保留确认缺席的最后一帧，事件时间为该帧的观察时间，而不是横跨可见与缺席的整段区间。其他核心事件仍保留各自引用；包含窗外或语音依据的事件不做这项收窄。失败任务也保留末段可见性、事件投影与写作策略的脱敏诊断，以区别观察错误、引用错误和核验否定。
- 活动的开始、停止、结束、加入或主动离开必须有不同时间的前后画面引用，或对应的可靠语音引用。一张静态画面、重复同一引用、不同帧号却相同时间都不能证明该变化，返回 `transition_evidence_incomplete`，候选事件在写作前清空，不能等待模型审核把它判为通过。此条件是必要条件而非事实证明：两张相同状态的画面也不支持起止，仍须独立事实核验。独立观察支持的末帧缺席仅是一项观察状态，不等于活动停止。
- 事实核验保存受限的布尔判定和原因代码，例如 citation_mismatch、unsupported_ending、missing_progression；不保存被拒绝的正文。请求失败不伪装成内容语义否定。
- 本地语音逐段过滤无语音、高压缩重复、低识别分数和低语言置信度；高质量简短中文不再只因不足 12 字丢弃。存储时间、字数和质量元数据，不存储原始转写。
- 远程重分析读取时间由声明文件大小按 128 KiB/s 保守估算，最少 300 秒、最多 1800 秒；保留原字节上限与 30 秒单次 socket 读取超时。原 512 KiB/s 假设会中止持续但偏慢的云盘传输，已用 200 MiB/600 秒模拟锁定并修复，超过 1800 秒仍中止。读取失败不能标成模型分析失败或覆盖旧简介。
