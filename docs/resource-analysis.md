# 资源分类与分析

资源类型与内容分类是两件事：MP4 可以是电影、课程、音乐或 NSFW 作品。资源库按内容检索，同时允许叠加文件类型、分析状态和关键词筛选。

## 使用

1. 在「同步策略与云盘挂载 → 资源分析与分类归档」设置兼容 Chat Completions 的模型服务；视觉资源需要支持图片输入的模型。
2. 选择参与分析的资源类型、置信度阈值、抽帧数和文件大小上限。开启自动归档时，新下载文件在完整落地后分析，上传前决定目录。
3. 「资源库」提供跨目录分类与真实云盘目录两种入口。NSFW 的细分菜单在选择「成人内容」后展开。
4. 已有文件可从真实目录选择「重新分析此资源」。这会读取该远程文件，调用配置的模型，并更新分类、标签与简介；不移动或重命名远程文件。每次最多两个后台任务，同一文件不会重复入队。

分类视图来自已完成下载记录和已重新分析的文件，不是一次递归扫描整个云盘。外部移动、删除的文件以真实目录为准。清理下载任务记录不会删除独立的资源库分析记录；在应用内删除远程文件时同时清理资源索引。

## 内容与细分

主分类覆盖电影、剧集、动漫、综艺、纪录片、课程、资讯、图书、办公资料、音乐、播客、有声读物、游戏、运动、旅行、生活、摄影、设计、压缩合集、软件、成人内容和待确认。

静态图片另有「插画与卡通」「表情包与梗图」「截图与界面」。普通卡通图片不需要剧情、动画片段或已知作品名才能归类；没有明确梗图结构时不强行归为表情包。真实照片及非情色的人物展示可归入摄影，不要求专业制作或叙事。

NSFW 按内容形式细分为专业制作、个人实拍、直播录制、订阅作品、角色扮演、二维动画、三维与游戏动画、AI 生成、音声与 ASMR、短片与表演、合集与剪辑、其他成人内容。细分用于中性归档；语言、字幕和制作来源只在证据支持时作为标签，不根据外貌推测国籍、身份或年龄。

「个人实拍」描述有可见依据的生活化实拍风格，不认证作者身份或私密关系，不以作者/平台署名为前提。「专业制作」「订阅作品」仍分别要求可核实制作署名或平台线索，普通转载水印不能代替这些依据。

NSFW 与普通写真按可证实的主要主题区分，不把“非露骨”等同“非成人”：明确成人向情色呈现也可能并不露骨。普通穿着、舞蹈、姿势或裸露本身不足以证明情色主题；医学、教育、艺术记录等非情色内容按实际用途分类。普通社区水印或转载标识不证明专业制作。非连续采样限制对完整情节的断言，但不应自动否定清晰画面已支持的宽分类。

课程分析学习主题、知识点、难度与适用人群；音乐分析音乐内容、曲风编制、演出录制形式；文档分析主题、结构和用途。NSFW 的各细分也使用各自的制作形式、镜头、声音或组织结构维度。

## 分析流程

`时间窗证据 → 分类概览识别 → 按类核验 → 视频事件与发展整理 → 基于事件的剧情/活动过程总结 → 内容事实核验`

第一阶段只能选择与资源类型兼容的分类。第二阶段必须保持同一资源类型、主分类与细分，并返回该分类规定的维度。服务端拒绝不匹配的类别、非法置信度、伪造的证据来源和缺失维度。非视频资源保留分类维度展示；视频将其折叠为分类依据，分类阶段不兼写阅读简介。分类使用原预算的概览帧；事件整理使用更完整的时间窗样本，写作阶段仅接收接受的事件记录。

如果第二阶段明确否定锁定的主类或细分，但其他协议字段均有效，可以通过 `correction` 提出一次新建议。只有资源类型兼容、类别/细分合法、置信度达到原门槛、引用来源有效且不同于原分类的建议才会进入重新核验。建议本身不是成功结果：必须使用同一证据，按新分类的维度重新生成分类依据（非视频为对应内容概览）并通过全部校验。没有有效建议、任何其他字段错误、明确拒绝或再次冲突都会停止，不循环纠错，不把 `false` 改成 `true`，不复用被拒绝的简介。最终置信度不会高于原判断或纠正建议中的较低值。

第一阶段选择 `other` 时，如果已有有效内容证据且数值达到原门槛，第二阶段先核验「已知信息／证据限制」，不原样重试分类。模型可在核验中提出上述受限纠正建议；如果仍不能确认，只追加有来源的中性观察，状态仍为 `needs_review`，不产生“已完成的待确认分类”。低于门槛或分类说明中明确拒绝分析时，不继续核验。

分类识别与核验提供可解析的 JSON 输出结构；核验结构预填实际资源类型、分类id、细分id和准确的维度键，避免让模型猜测“原分类id”或把显示文字当id。非成人资源没有细分，仅将其 `null` 或“无”兼容为空字符串；成人细分、主分类、资源类型及内容一致性仍严格校验，不能通过空值覆盖真实细分。

第一阶段同时提取最多4条中性内容观察，每条必须引用本次实际提供的证据类型。分类不确定、置信度不足或后续简介失败时，仍可保留这些观察；它们显示为「内容观察／已识别内容」，不冒充已确认分类或正式简介。悬浮预览、详情、搜索及任务说明均可使用，隐私模式下悬浮内容仍隐藏。模型未提供有效观察时不代为编造。观察与引用校验不等于人工事实核验。

分类输出模板按「资源类型 → 内容观察 → 简短依据与来源 → 主类、细分和置信度」排序，与先观察再分类的指令一致。仅改变生成顺序，不预填期望类别，也不绕过后续一致性校验。

低置信度、证据不足或两阶段结果不一致时进入「待确认」，不强制归档。提取或模型错误不会阻止下载和上传。分类仍是模型推断，不代表对内容的人工核验；详情显示证据范围和局限。

模型请求按分类、分类核验、事件整理、写作及内容事实核验分别计时。超时、连接中断、HTTP 408/429/500/502/503/504/524 及 JSON 对象语法错误，每阶段合计最多重试一次，复用已提取证据；重试超时上限为设置值的两倍（最多300秒）。鉴权失败、明确拒绝（含可识别的纯文本拒绝）、非 JSON 散文、接口封装错误及输出截断不自动重试。524 单独标记为模型网关等待上游超时，延长本地等待不能取消服务侧限制。基础完整视频路径为五次请求，「更新简介」省去分类与分类核验两次；成人分类另加一次叙事模式判定，成人 activity 另加一次主活动核对，封闭事件投影省去写作请求，长视频另加末段观察和末帧独立观察各一次。非视频通常为两次。重试和受限纠正可能增加费用，具体流程见 [视频剧情与片段总结](narrative-summary.md)。

grok-4.6 的归档请求显式设置 `reasoning_effort: low`，避免默认高推理量挤占有限请求时限；其他未核实的模型名称和别名不自动附加该参数。高级配置 `video_classifier.reasoning_effort` 可显式选择 `low / medium / high / xhigh`，或用 `default` 保留服务端默认行为；具体兼容性仍取决于配置的模型服务。该设置不改变置信度门槛、抽帧数量或语义校验。依据：[grok 推理参数](https://docs.x.ai/developers/model-capabilities/text/reasoning)。

分析详情保留失败阶段、请求次数、耗时、HTTP状态、证据来源和当前阈值，不保存密钥、接口地址、原始模型回复或请求素材。模型主动选择 `other` 记为 `model_uncertain`，与低于阈值的 `low_confidence` 分开；模型给出的简短证据缺口显示为「模型说明（待核实）」。没有提供说明时明确提示缺失，不代为编造。人工重新分析也会同步对应下载任务的分析状态与说明，未完成的分析不会清除已提取证据。

简介校验逐项记录资源类型、主分类、细分、分类一致性布尔值、维度结构及证据来源的结果。失败说明指出具体字段，不再仅提示笼统的“结果不一致”；`diagnostics.validation` 保存允许枚举的期望值、实际值类型、已知维度名与未知键数量，不保存未知枚举值、未知键名或被拒绝的简介正文。真实否定分类与返回字段格式错误分别标记，校验通过也保留脱敏记录以便对比。

`diagnostics.validation_history` 保留每次核验的脱敏结果，`corrections` 仅保留已校验的原/新分类枚举、置信度和来源类型；纠正请求以 `revision: 1` 区分。`request_options` 记录实际发送的推理量参数，不包含服务地址或密钥。

旧版成人专用模板产生的简介标为「旧版待更新」，不会作为新分类的已验证简介展示。原有 `nsfw` 路径仍可在成人分类入口找到，但旧目录名不是已确认的细分证据。

## 证据与依赖

| 资源 | 可用证据 | 限制 |
| --- | --- | --- |
| 视频 | FFprobe 探测时长；FFmpeg按时间窗取局部前后画面，语音可对齐采样 | 分类概览最多16帧；事件整理默认最多24帧、8个时间窗，不能声称覆盖完整情节 |
| 图片 | Pillow 缩放后的图像 | 单张图像不证明前后事件；动画图片仅取当前帧 |
| 音频 | 可选 faster-whisper 语音转写 | 默认关闭，总秒数默认180、最多600，长音频分段采样；转写不等于分析音色或纯音乐 |
| 文档 | TXT/Markdown/CSV/JSON/字幕等文字，PDF、DOCX、PPTX、XLSX、EPUB、OpenDocument 的部分正文 | PDF 依赖 pypdf，最多前6页，无扫描页 OCR；旧二进制 Office 等格式待确认 |
| 压缩包 | ZIP/TAR 的前150项文件清单 | 不解压或执行文件，不将清单伪装成正文；RAR/7z 暂为待确认 |
| 软件与其他 | 扩展名、文件类型 | 不执行程序，不凭名称虚构功能或宣称安全性 |

文档读取有字符、成员大小和累计大小限制。文件名只参与本地格式识别、展示和检索；文件名、频道名、发布文案不再加入分类或简介的模型请求，避免宣传性标题把分析变成对标题的验证。分类和核验直接使用实际画面、提取正文和本地转写，视频写作只使用已接受事件，事实核验再对照同批证据；素材本身包含的文字仍是不可信内容，不能作为指令。旧调用的 `text_hints.file_name` 仍可辅助本地识别格式，其他辅助文案不再发给模型。

视频分析默认采用时间窗方案：最多8窗、每窗最多3帧，总数默认24帧，解码预算120秒。较长视频在默认180秒语音预算中覆盖开场60秒、末段60秒，以及分散在中间的6个10秒窗口。最低6帧仍保留开中末三组，短片保留均匀时间窗。按实际时间排序，不为了较亮画面丢掉开头或结尾。分类只接收原分类预算内的概览子集，事件整理及事实核验使用时间窗样本；末段及主活动独立核对也复用这些帧。时长不可用时退回有限固定时间点；解码失败或预算耗尽仅使用实际取得的画面。此方案不改变原视频、不替代全片观看或场景检测，仍可能漏掉短暂事件。折叠依据显示实际采样方法、时间和限制。

黑底或留边中的有效内容不会仅凭整张平均亮度被丢弃：对低亮度候选另外检查中央区域的亮度和对比，区分中央仍可见的画面与纯暗背景加角落水印。该检查不提亮、不重绘、不改变原始像素内容，仍通过同一候选数量和发送数量限制。

## 配置兼容

继续使用已有的 `video_classifier` 配置节和 API 凭据，避免升级时丢失配置。新增字段：

```yaml
video_classifier:
  enable: true
  resource_types: [video, image, audio, document, archive, software]
  max_frames: 6
  narrative_frames: 24
  min_confidence: 0.65
  max_file_size_mb: 2048
  transcribe: false
  max_audio_seconds: 180
  organize_folders: true
```

`api_key`、`api_base`、`model`、`timeout` 沿用原设置，`max_video_size_mb` 是文件上限的旧兼容字段。修改参数后保存会保留同一节中的其他字段。`resource_types: []` 表示不分析任何类型。

新文件目录为 `分类组/分类/原相对路径`；成人内容为 `nsfw/细分/原相对路径`。保留来源、日期与文件名；不会丢弃中间目录，不覆盖已存在的目标文件。关闭 `organize_folders` 仍可生成分析并使用分类视图。

## 代码与存储

- `module/resource_analysis/taxonomy.py` 是后端规则、目录和前端菜单共用的分类定义；增加类型时在此定义适用资源类型、分析方向与识别提示。
- `evidence.py` 提取有界证据；`service.py` 封装分类识别、分类核验与视频独立写作；`summary.py` 负责面向读者的简介投影和引用检查；`paths.py` 只规划目录。
- `library.py` 负责按完整相对路径索引、过滤、分页、旧数据展示与持久化；`jobs.py` 管理单文件重分析。
- `webui/src/library/` 提供菜单、详情、预览与前端资源模型；`FileManager` 协调导航和筛选，过期请求会被取消。
- `module/video_classifier.py` 保留旧 `classify_video` 调用入口，委托给新框架。

分析结果包含 `schema_version: 2`、资源类型、主分类、细分、置信度、状态、维度、标签、证据来源和限制；兼容新增 `content_description`、带来源的 `observations` 和 `sampling`，旧结果无需迁移。下载分析缓存的流程版本为26，推理量与剧情帧预算参与缓存指纹，旧流程缓存不替代新流程的分析；不会自动批量重分析已有资源。新下载结果随现有下载历史持久化；独立资源库按 WebDAV 地址、根目录和用户名隔离，写入 PostgreSQL `settings`（配置数据库时）及 `.cache/resource-library/` 的原子 JSON 备份。无数据库部署应保留该目录。

视频的 `summary_sentences` 同时绑定 `event_refs` 与实际证据引用，`summary_quality.version` 为5，`narrative.version` 为2。`narrative` 保存 story/activity/insufficient 模式及有时间来源的主线事件。每项先区分 `core`（主要内容）、`progression`（实质发展）和 `detail`（次要观察），细节经安全与引用检查后不进入写作；主线首尾仍必须覆盖。剧情用2–4句概述人物处境、发展与已知结果；活动片段用1–3句概述具体活动及变化，不强行编故事。纯环境与构图、重复空话、非中文、无依据的全片/声音断言不能通过。独立事实核验逐事件、逐句对照证据，同时核验叙事模式、信息层级与采样内容覆盖；任何漏项、否定、错误格式或拒绝都不能得到 `audit.status: passed`。分类 `complete` 与简介 `ready` 分离；界面区分「剧情梗概／片段内容／剧情待确认」，旧版自检通过的简介同样提示更新。事件与分类依据默认折叠；卡片、悬浮与详情共用状态投影。格式与引用完整性不等于语义事实证明，模型核验也不等于人工看完整部视频。

成人视频简介使用中性人物称呼，不把背影、服装或表情解读为性别、身份、心理感受或同意情况。对带数量词的性别称呼，本地仅作保守泛化（如「一位男子」变为「一人」），保留人数、可见动作、服装与引用；不声称这一步能识别人物身份。其他内容分类的简介不经过这一称呼转换。

视频语音使用原总秒数预算，与事件时间窗对齐。逐段检查语言置信度、无语音概率、平均对数概率与异常重复，低可靠性转写不会进入模型。`sampling.audio` 只保存时间窗与质量元数据，不保存原始转写；尝试但无法解码的时间窗不计入成功采样。可靠转写只能支持对应片段的文字或语言线索，不能证明音色、配乐或完整音轨。

长视频默认180秒预算保留连续前60秒与末60秒，其余60秒分散到中段；总计最多8窗、24帧。不能因取到最后一帧就假定已覆盖结束前的过程；短视频与最低帧预算保留各自的有界覆盖方式。

超过300秒且有时间窗的视频，在整理事件前先独立读取既有末窗最多3帧，再隔离读取同一最后一帧：不看候选简介，逐项映射回原始帧号和时间。增加两次有界模型调用，不增加媒体取样量；观察作为待核对来源交给主线整理和事实核验，不直接展示为剧情。只有末帧确认缺席时，该状态不能反向扩展到此前仍可见的画面。观察失败或被拒绝就停止候选，不能退回整批读取把失败绕过去。

隔离末帧只判断人物是否可辨认，不生成活动描述；visible、not_visible、unclear 均保留其含义，不把 unclear 强制转换成缺席。原末窗活动观察与独立可见性分别标来源，前者不会因只做可见性检查而丢失。两者冲突时继续以实际图像核验，不能把结构合法的观察视作事实真值。

活动起止、加入、主动离开等变化另有时间证据门槛：至少引用两个不同时间的画面，或引用明确支持该变化的可靠语音。一张静态画面不够，重复引用也不够；候选在写作前拒绝，不把缺席或坐起擅自解释为活动结束。引用足够仍须独立事实核验，不能凭数量认定事实成立。

`grok-4.6` 显式请求 `response_format: {type: json_object}`，避免中性状态检查返回非JSON正文；沿用原有低推理量及拒绝处理。该格式由 [xAI Structured Outputs](https://docs.x.ai/developers/model-capabilities/text/structured-outputs) 文档支持，并已在用户指定代理验证。其他模型或别名不自动附加此参数，JSON合法也不代表事实核验通过。

短中文对白可在更严格的分数条件下保留，不再只按12字门槛丢弃：至少4个不同中文字符，无语音概率≤0.2、平均对数概率≥-0.4、压缩比≤2.0、语言概率≥0.8。低分短句、重复语气声仍排除；新增 `accepted_characters` 只用于脱敏诊断，不保存正文。

成人活动简介聚焦主要内容，不展开露骨细节，也不能用衣着或普通按摩冒充主体活动。同一活动跨窗口观察合并；只有静态证据仍保持待确认。密集姿势清单、空泛变化、未经支持的末段延续不能通过。事件句至少6个中文字符、最多160字符，不设正文总字数下限。封闭活动事件直接投影为正文，避免润色新增起止和因果，仍须 Grok 逐项事实核验；真正 story 仍按事件写剧情。主活动、末段变化及拒绝处理不因写作策略而放宽。受限纠正规则详见 [视频剧情与片段总结](narrative-summary.md)。

已有视频重新分析先产生候选结果；分类或简介不合格时不更新原索引和下载历史，本次任务单独报告失败及脱敏问题代码。首次分析没有旧结果时可保留已确认分类并标记简介待完善。相关复现及真实验收见 `docs/narrative-summary.md`。

分类确认后，`narrative` 阶段先建立事件记录，时间由证据引用计算。完全相同的连续观察合并并保留引用与时间跨度，不用字符串相似度抹掉开门/关门这样的不同动作。事件不足、引用无效或不合适的内容不会进入写作阶段。`summary` 阶段只按已接受事件生成非露骨的中文总结，每句引用事件并覆盖关键发展；明确拒绝不重试，不保存拒绝草稿。实现与验收详见 [事件与剧情总结](narrative-summary.md)。

已确认分类的视频另有「更新简介」入口（`POST /api/library/analyze`，`mode: "summary"`）。它重新提取证据，运行事件整理、写作及内容事实核验，保留已有分类、置信度、标签与分类依据；`diagnostics.classification_reused` 和原分类时间明确记录复用，详情折叠区同步标明，不能当成新的分类校验。未确认分类或非视频资源在排队读取前被拒绝。默认 `mode: "full"` 与「重新分析此资源」保留完整分类流程。两个模式均有不合格候选不覆盖旧结果的保护。
