# 来源文案与时间序列分析：第一版

## 已实现

- 沿用本地预处理和现有 Grok 配置；未引入阿里云或另一家模型服务。
- 下载时保存未经文件命名清洗的 caption、消息正文、原始文件名及精确消息/媒体组关联。命名缓存不再作为原文来源；不会配对相邻但无关联的消息。
- 原文随下载历史进入目录索引，手动重新分析也读取同一份 source_context。没有历史文案的资源仍标记缺失，不编造回填。
- share_source_text 默认 false，只有严格布尔 true 才能发送清理后的发布者文案与原始标题。聊天/消息 ID 和频道名称不作为字段附带发送。正文中的其他信息不等于已完成匿名化。
- 分类与最终事实核验不读取发布者文案；叙事模式和事件整理可在授权后使用它寻找线索。文案不是 evidence_ref，不能单独支持任何事件。界面原文独立标为未经核实。
- use_subtitles 默认 false。启用后读取本地同名 SRT/VTT 或首条可转换内嵌字幕，保留原时间戳和字幕来源。限制文件 2 MiB、正文 12000 字符，超预算分散选取，不只保留片头。无字幕时沿用本地转写设置。
- 成人向事件保留中性活动分类，同时新增自由表述的 content 事件，需真实画面/对白引用；写作必须保留其具体含义，仍禁止露骨描述及身份、年龄、同意、心理推断。最终事实核验不能跳过。
- 简短、单句的活动 content/context 事实可直接保留文本与引用生成简介，避免二次改写新增目的或因果；仅用于已通过事件校验的 activity，复杂段落和 story 仍使用写作步骤，最终事实审核和具体信息门槛不变。
- 成人资源的 story 模式必须提供有直接引用的具体问题/处境候选，不能只返回模式标签。候选须通过原事件校验并保留在主线中；写作与盲审接收必需事件编号，遗漏问题不通过，不自动注入事件来挽救失败或拒绝。
- story 事件通过 premise_ref 明确承接问题，允许正常改写但必须保留引用；终审同时核对原问题候选、实际证据、承接事件和正文，不以逐字匹配或关联编号本身证明事实。旧版无关联标记的记录仍仅可按原文匹配。
- 标准采样沿用有界时间窗；手动 deep 增至最多 48 帧、16 个时间窗，语音预算扩大但最多 600 秒，不会自动开启转写或任何新数据外发。
- 深度模式最多独立读取 4 个窗口，局部编号映射回全局画面/对白 ID，时间由服务器按引用计算；局部观察仅是待核验候选，不自动当成事实。
- 深度模式本地低分辨率镜头变化扫描最多 45 秒或 128 个候选，固定首尾及时间分布。失败保留固定时间窗，不把扫描失败当成无剧情。
- 详情页原文、深度采样按钮和依据折叠显示；不增加首页面板。新增外发选项在设置中解释数据用途，默认关闭。
- 自动下载分析缓存纳入文件内容 SHA-256、来源文案、配置和 pipeline 33。失败候选保留原已确认结果；手动重分析继续保留旧结果。

## 明确限制 / 后续验收

- 已开始授权资源 308、312 的 Grok 对照复测，尚未通过内容质量验收；详见同目录 video-context-test-20260908.md。不能凭单元测试或模型自评宣称简介质量达标。
- 字幕不等于真实对白。当前没有自动听音校准字幕偏移；云端重分析仅下载所选资源，未额外查找云端同名字幕。
- 未实现新资源自动回溯 Telegram 历史以找回丢失文案，也不自动获取邻近消息。媒体组原文缓存是有界的进程缓存。
- 深度分析仍是采样，不是逐帧理解或全片语音转写。现有一次有界补采样：服务器根据实际证据时间、活动冲突、变化证据缺口与未覆盖区间自动选窗，不需要用户提供剧情时间；不接受发布者文案或模型任意指定的新时间作为事实。
- 该补采样最多增加 12 帧；若本轮旧对白明确判为不可理解，则排除其文本，并在尚未访问音轨中独立搜索最多 16 个窗口、600 秒，否则沿用最多 180 秒补充预算。不会恢复已排除的旧转写，也不会自动启用原本关闭的转写。
- 对白阶段无法安全中性概括的文本同样从后续证据中排除，补采样不重新获取该语音；中性画面分析与最终核验仍然执行，不以重新请求规避排除结论。
- 新提取的带逐段文本的对白先独立筛选，再判断剧情。保留可用片段并重建引用编号，模型明确拒绝即停止；不可理解或不适合中性概括的片段不参与后续。补采样可检查尚未访问的音轨，但不得重新读取已处理区间；旧版整批排除记录不以此重新开启。
- 简介直出按事件实际引用保留来源边界：纯语音事实明确标注音轨，转回视觉事件时用分号和画面来源区分，不以逗号拼接暗示同一人物或因果。写作与终审采用同样约束；时间重叠不证明音画人物对应。
- 事件整理及独立终审单独核验职业身份与信息主次：动作不证明职业，同一活动的局部步骤不能冒充新增主要内容。提示约束不等于真实语义保证，候选仍需内容验收，不能仅凭自动通过保存复测结果。
- 分段候选交给全局整理去重和选择，不在整理之后强制追加为主要事件。最终审核另接收原候选及其引用，核查重要信息是否遗漏；重复、局部细节或无依据候选不要求恢复，通用简介仍不能通过质量门槛。
- 主活动观察与有效活动事件冲突时，最多进行一次定向事件复核：原图、原始候选及观察均待核验，不强制采信任一标签。复核后仍须通过事件结构、主活动一致性、末段约束和独立终审；拒绝、错误结构或持续冲突继续失败，不改分类、不恢复不可靠语音、不绕过最终事实审核。
- 成人 activity 模式的主线由服务器从逐帧编码读数生成，每帧单独请求（批量读图会给整批同一个标签）。标准模式读 7 张分散画面；深度模式读约 40 张分散画面，每张独立读 3 次取多数，再按相邻 5 帧多数决平滑（单帧单次读数在两轮之间只有约四分之三一致，三帧短片段并不比单帧稳定，15 帧各读 3 次仍不足以定位阶段；平票取本帧读数）。连续同码读数构成阶段；夹在同码两段之间的孤立读数先删除并合并邻段，其他孤立读数随后删除；稀疏采样保留首尾孤立读数，密集读数（≥20 帧）不保留。只有形成阶段的活动才是本视频的活动。
- 观看者确认 308 全程为成人内容且有对话，而逐帧读数把大量画面读成"按摩"并被拼成不存在的交替阶段。修正：按摩读数与亲密互动读数交替出现时视为同一连续成人活动，按摩只作为"其间有按摩环节"记录，不再写成阶段；单独一段按摩接一段亲密互动仍是顺序。仅有该合并主线且没有具体内容句时，仍按标签式简介拦截。
- 语音：本地转写改为每个文件一次语言判定（三段 30 秒探测多数）并固定到每个窗口，beam 5（原按窗口自动判语言、beam 1，在实际口语素材上丢掉大部分中文对话）。每窗记录已接受片段数、语音秒数和平均对数概率。至少三个窗口、跨前后两半都检出中文语音时，服务器生成"片中有中文对话"的内容句，引用自身的 speech_presence 证据；模型不能凭画面主张它。对话具体含义仍经原筛选，未通过时不写入。
- 对白含义只有一个来源：逐段筛选阶段。全局事件整理也能看到保留的转写，但它仅引用语音的 content/context 若不是筛选给出的陈述即丢弃（诊断 model_speech_events_dropped）。"片中有中文对话"并入首句。全局模型照抄提示例句的空话（"组织活动并展示任务变化"）判为标签复述；证据跨度超过 2 分钟的内容句不加时间锚点；投影时具体内容合为一句、结尾单独一句。
- 对白筛选增加话题级分支（reason=topics）：内容零碎但能辨认在聊什么时，返回 1–3 个 2–10 字的中性话题词，只命名话题、不引用原话，露骨、年龄、身份、同意相关词一律无效（无效即当作无话题，不判失败）。服务器把各段话题合成一句"对话中谈及 A、B 和 C"，引用对应语音段，仍经终审。这是用户 2026-09-11 决定的放宽，目的是让"两人边做边聊什么"进入简介。
- 逐帧读数先于路由：成人资源先读帧再判叙事模式；编码读数中亲密互动（含合并的按摩）占六成以上时，无论对白说什么都走 activity（诊断 route_override=dominant_activity）。真实复测中一条具体对白就足以让路由选 story，然后写作模型把全片写成"按摩互动"。
- 路由守卫：成人资源在逐段筛选只得到话题级对白（没有具体含义）时不能进入 story；前提只是"面对 X 的处境"之类标签复述的 story 也回落到 activity（诊断 route_override）。真实复测中话题级对白一出现，路由就判 story，写作模型随即编出"女子面对按摩的处境…画面变暗"并通过了三重终审。
- 终审否决的附加陈述（progression、content、context 任一）在主线全部受支持时删除并重新终审一次，不再只限于"不再出现"一句；诊断 audited_ledgers 保留每次终审面对的事件与句子，便于事后定位。
- 阶段句由服务器写：某阶段至少 3 帧且跨度不小于 60 秒或时长 10% 时视为可锚定，按顺序写"开头为 A，约 2–5 分钟转为 B，约 5–8 分钟回到 A，末段回到 B"；可锚定阶段之间的零散读数写"前段 A 与 B 交替出现"，单帧只写"约 N 分钟时再次出现 A"，末段一词只给到达片尾的多帧阶段。没有可锚定阶段时退回"A 与 B 交替进行"，只有 2.5 倍以上差距才写"以 A 为主"。全局模型只贡献 content/context。
- 具体内容句由服务器改写措辞：分段读图把主要人物称为"主体"，正文改为"一人/对方"，不保留性别指称（少量画面不能确认性别），画面内容按自身证据加"开头/约 N 分钟时/末段"锚点，含义与引用不变。单纯的坐到床上、起身、走到镜头前等位置变化归为 detail，不成为 content。多条简单的 content 挂在服务器阶段句上时直接投影，不再交给写作模型（写作模型会丢掉锚点并带回占位称呼）。
- 深度模式分段每窗独立读取 3 次，只保留在至少 2 次读取中重复出现（同义表述）的候选；单次读取的场景描述或不安全候选仅丢弃该次读取，窗口全部读取都不可用才失败。重复候选若被全局整理丢弃或替换成标签式改写，由服务器作为 content 带入事件记录，仍经事件校验与独立终审，终审否决即不保留。
- 末帧可见性在深度模式读取 3 次取多数；终审仅否决“不再出现”且该判断与隔离末帧读数冲突时，删除该主张后重新终审，不发布也不坚持。深度模式终审独立请求 3 次，按事件、句子和覆盖逐项取多数，平票不算支持。分析缓存版本 37。
- 正常抽帧与补采样使用同一空间分辨率策略：宽度最多 1024、不放大小源，最终图像编码最长边不超过 1024。分析缓存版本 34。提高分辨率仅保留更多可见信息，不能替代时间覆盖或事实核验。
- 活动事件若包含多项自由表述的 content，进入现有写作阶段去重概括，不直接拼接观察原句；简单分类词项与独立对白仍可直出。写作只接收事件记录，继续检查引用、具体含义、主线和独立事实审核，不以顺畅措辞替代真实性。
- 文件内容哈希用于最终结果复用；尚未建立跨任务持久化的抽帧/转写缓存，临时素材在分析结束后清理。
- 未修改用户模型配置或开启全局文案外发。后续复测按用户单独授权发送 308、312 的抽帧、本地转写和清理后的来源文案；字幕外发仍关闭，原视频与音频不发送给模型。

测试不把模拟模型认可当作真实视觉理解质量证明。
